## 1. はじめに

### 1.1 目的

本文書は、Rust AED (Agentic Document Extraction) ライブラリの機能要件および非機能要件を定義します。

### 1.2 スコープ

本プロジェクトのスコープは以下の通りです：

**スコープ内**
- Claude Vision API を使用した OCR 機能
- 日本語縦書き・横書きテキスト抽出
- 構造化データ抽出（JSON 出力）
- Rust ライブラリとしての提供

**スコープ外**
- ローカル LLM 対応（将来バージョン）
- 手書き文字認識の高精度化
- リアルタイム動画 OCR

### 1.3 用語定義

| 用語 | 定義 |
|------|------|
| AED | Agentic Document Extraction の略 |
| OCR | Optical Character Recognition（光学文字認識） |
| 縦書き | 日本語の伝統的な右から左、上から下への書字方向 |
| 構造化抽出 | ドキュメントから特定のスキーマに従ってデータを抽出すること |
| プリセット | 特定の用途に最適化されたプロンプトテンプレート |

## 2. 機能要件

### 2.1 テキスト抽出機能

#### FR-001: 基本テキスト抽出

| 項目 | 内容 |
|------|------|
| ID | FR-001 |
| 名称 | 基本テキスト抽出 |
| 優先度 | 必須 |
| 説明 | 画像または PDF からプレーンテキストを抽出する |

**入力**
- 画像ファイルパス（PNG, JPEG, GIF, WebP）
- PDF ファイルパス
- Base64 エンコード済み画像データ

**出力**
```rust
pub struct ExtractionResult {
    /// 抽出されたテキスト
    pub text: String,
    /// 信頼度スコア (0.0-1.0)
    pub confidence: f32,
    /// 検出された言語
    pub language: String,
    /// テキスト方向
    pub direction: TextDirection,
    /// 処理時間
    pub processing_time: Duration,
}
```

**受け入れ基準**
- [ ] PNG, JPEG, GIF, WebP 形式の画像を入力できる
- [ ] PDF ファイル（最大 100 ページ）を入力できる
- [ ] 抽出されたテキストを UTF-8 文字列で返す
- [ ] 処理に失敗した場合は適切なエラーを返す

---

#### FR-002: 日本語縦書き対応

| 項目 | 内容 |
|------|------|
| ID | FR-002 |
| 名称 | 日本語縦書き対応 |
| 優先度 | 必須 |
| 説明 | 縦書きの日本語テキストを正しい読み順で抽出する |

**入力**
- 縦書きテキストを含む画像
- テキスト方向の指定（オプション）

**処理フロー**
```
1. TextDirection::Vertical が指定された場合
   → 縦書き用プロンプトを使用
2. TextDirection::Auto の場合
   → Claude に自動判定させる
3. 右から左、上から下の順序でテキストを抽出
4. ルビ（振り仮名）は「漢字《ふりがな》」形式で出力
```

**受け入れ基準**
- [ ] 縦書きテキストを右から左の列順で抽出できる
- [ ] 各列内のテキストは上から下の順序で抽出される
- [ ] ルビ付き文字を適切に表現できる
- [ ] 縦書き・横書き混在文書を処理できる

---

#### FR-003: 構造化データ抽出

| 項目 | 内容 |
|------|------|
| ID | FR-003 |
| 名称 | 構造化データ抽出 |
| 優先度 | 高 |
| 説明 | 指定されたスキーマに従って JSON データを抽出する |

**入力**
- 画像または PDF
- 抽出対象の Rust 型（`serde::Deserialize` 実装）

**使用例**
```rust
#[derive(Deserialize, JsonSchema)]
struct Invoice {
    #[serde(rename = "会社名")]
    company_name: String,
    #[serde(rename = "合計金額")]
    total_amount: i64,
    #[serde(rename = "明細")]
    items: Vec<InvoiceItem>,
}

let invoice: Invoice = client
    .extract_structured::<Invoice>("invoice.png")
    .await?;
```

**受け入れ基準**
- [ ] 任意の `Deserialize + JsonSchema` 型に抽出できる
- [ ] 日本語フィールド名をサポートする
- [ ] ネストされた構造体・配列を処理できる
- [ ] 抽出失敗時に詳細なエラーを返す

#### FR-004: バッチ処理

| 項目 | 内容 |
|------|------|
| ID | FR-004 |
| 名称 | バッチ処理 |
| 優先度 | 高 |
| 説明 | 複数ファイルを効率的に並列処理する |

**入力**
```rust
pub struct BatchConfig {
    /// 並列実行数（デフォルト: 5）
    pub concurrency: usize,
    /// 失敗時の継続（デフォルト: true）
    pub continue_on_error: bool,
    /// 進捗コールバック
    pub on_progress: Option<Box<dyn Fn(usize, usize) + Send>>,
}
```

**受け入れ基準**
- [ ] 指定された並列度で処理できる
- [ ] 一部失敗しても残りを継続できる
- [ ] 進捗状況をコールバックで通知できる
- [ ] 全結果を `Vec<Result<ExtractionResult>>` で返す

### 2.2 プリセット機能

#### FR-005: プリセットシステム

| 項目 | 内容 |
|------|------|
| ID | FR-005 |
| 名称 | プリセットシステム |
| 優先度 | 高 |
| 説明 | 用途別に最適化されたプロンプトテンプレートを提供する |

**組み込みプリセット**

| プリセット | 用途 | 特徴 |
|-----------|------|------|
| `General` | 汎用 | 自動判定、基本抽出 |
| `JapaneseBook` | 日本語書籍 | 縦書き、ルビ、改ページ |
| `Manga` | 漫画 | 吹き出し、効果音 |
| `Invoice` | 請求書 | 金額、明細、日付 |
| `BusinessCard` | 名刺 | 氏名、連絡先 |
| `Receipt` | レシート | 店舗、日時、商品 |
| `Form` | フォーム | ラベル・値ペア |
| `Table` | 表 | 行・列構造 |

**カスタムプリセット**
```rust
let custom = OcrPreset::custom()
    .system_prompt("あなたは医療文書の専門家です")
    .extraction_prompt("診断名と処方薬を抽出してください")
    .build();
```

**受け入れ基準**
- [ ] 全ての組み込みプリセットが利用可能
- [ ] カスタムプリセットを作成できる
- [ ] プリセットをファイルから読み込める（TOML/YAML）

#### FR-007: リトライ処理

| 項目 | 内容 |
|------|------|
| ID | FR-007 |
| 名称 | リトライ処理 |
| 優先度 | 高 |
| 説明 | 一時的なエラー時に自動リトライする |

**リトライ対象**
- 429 Too Many Requests（レート制限）
- 500/502/503/504 サーバーエラー
- ネットワークタイムアウト

**設定**
```rust
pub struct RetryConfig {
    /// 最大リトライ回数（デフォルト: 3）
    pub max_retries: u32,
    /// 初期待機時間（デフォルト: 1秒）
    pub initial_delay: Duration,
    /// 最大待機時間（デフォルト: 60秒）
    pub max_delay: Duration,
    /// 指数バックオフ係数（デフォルト: 2.0）
    pub backoff_factor: f64,
}
```

**受け入れ基準**
- [ ] レート制限時に `Retry-After` ヘッダーを尊重する
- [ ] 指数バックオフで待機時間を増加させる
- [ ] 最大リトライ回数を超えたらエラーを返す

#### FR-008: キャッシュ機能

| 項目 | 内容 |
|------|------|
| ID | FR-008 |
| 名称 | キャッシュ機能 |
| 優先度 | 中 |
| 説明 | 同一入力に対する重複 API 呼び出しを回避する |

**キャッシュキー生成**
```rust
// ファイルハッシュ + プロンプトハッシュ + モデル
let cache_key = format!(
    "{}:{}:{}",
    sha256(image_data),
    sha256(prompt),
    model_id
);
```

**設定**
```rust
pub struct CacheConfig {
    /// キャッシュ有効化（デフォルト: true）
    pub enabled: bool,
    /// キャッシュディレクトリ
    pub directory: PathBuf,
    /// TTL（デフォルト: 24時間）
    pub ttl: Duration,
    /// 最大サイズ（デフォルト: 1GB）
    pub max_size: u64,
}
```

**受け入れ基準**
- [ ] 同一入力で API を再呼び出ししない
- [ ] TTL 経過後にキャッシュが無効化される
- [ ] キャッシュサイズが上限を超えたら LRU で削除

## 3. 非機能要件

### 3.1 性能要件

#### NFR-001: レスポンス時間

| 項目 | 要件 |
|------|------|
| 単一ページ処理 | 5秒以内（P95） |
| バッチ処理スループット | 10ページ/分以上 |
| API レイテンシ | ネットワーク込み 3秒以内 |

#### NFR-002: リソース使用量

| 項目 | 要件 |
|------|------|
| メモリ使用量 | 500MB 以下（100ページ処理時） |
| ディスク使用量 | キャッシュ 1GB 以下 |
| CPU 使用率 | 画像エンコード時 50% 以下 |

---

### 3.2 信頼性要件

#### NFR-003: 可用性

| 項目 | 要件 |
|------|------|
| API 障害時 | エラーハンドリング + リトライ |
| ネットワーク断 | タイムアウト検出 + 通知 |
| 不正入力 | 早期バリデーション + エラー |

#### NFR-004: エラーハンドリング

```rust
pub enum AedError {
    // 認証エラー
    MissingApiKey,
    InvalidApiKey,

    // API エラー
    ApiError { status: u16, message: String },
    RateLimited { retry_after: Duration },

    // 入力エラー
    UnsupportedFormat(String),
    FileTooLarge { size: u64, max: u64 },
    PageLimitExceeded { pages: u32, max: u32 },

    // 処理エラー
    ExtractionFailed(String),
    JsonParseError(serde_json::Error),

    // I/O エラー
    FileNotFound(PathBuf),
    IoError(std::io::Error),
}
```

## 4. 制約事項

### 4.1 技術的制約

| 制約 | 影響 |
|------|------|
| Claude API レート制限 | 並列度に上限 |
| リクエストサイズ 32MB | 大きな PDF は分割必要 |
| 100ページ/リクエスト | 長い PDF は分割必要 |
| ネットワーク必須 | オフライン利用不可 |

### 4.2 ビジネス制約

| 制約 | 影響 |
|------|------|
| API 従量課金 | コスト管理必要 |
| 利用規約遵守 | 特定用途に制限 |
